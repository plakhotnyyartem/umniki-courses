# 🦉 Умники — курсы английского и математики для детей 5–14 лет

**Стек:** Python 3.11+, FastAPI, SQLAlchemy 2, SQLite · фронтенд на чистом HTML/CSS/JS без сборки.

## Запуск

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
cd backend
../.venv/bin/python -m app.seed      # демо-данные (ПЕРЕСОЗДАЁТ базу!)
../.venv/bin/uvicorn app.main:app --reload --port 8010
```

Откройте http://localhost:8010. Документация API (Swagger) доступна по адресу http://localhost:8010/docs.

## Ссылка для друзей (временная)

1. Один раз смените демо-пароли. По публичной ссылке пароль `demo12345` небезопасен:
   `cd backend && ../.venv/bin/python -m app.reset_demo_passwords`. Новые пароли окажутся в `data/demo-accounts.txt`.
2. Запустите сайт (команда выше), затем во втором терминале: `cloudflared tunnel --url http://localhost:8010`.
3. Отправьте друзьям адрес вида `https://….trycloudflare.com` из вывода команды.

Ссылка работает, пока Mac включён и оба процесса запущены. После перезапуска туннеля адрес меняется.

## Постоянный сайт: Render + Neon (бесплатно)

База данных — PostgreSQL на [Neon](https://neon.tech), сайт — на [Render](https://render.com).
Все настройки описаны в `render.yaml`.

1. **Neon:** зарегистрируйтесь, создайте проект (регион *Frankfurt*) и скопируйте *Connection string* вида `postgresql://…`.
2. **Render:** войдите через GitHub → **New → Blueprint** → выберите этот репозиторий. Render попросит ввести:
   - `DATABASE_URL` — строка из Neon;
   - `ADMIN_EMAIL` — ваш email для входа в админку;
   - `ADMIN_PASSWORD` — пароль админа, не короче 12 символов.
3. Через 2–3 минуты сайт откроется по адресу вида `https://umniki.onrender.com`.

При первом запуске сайт сам создаёт администратора и загружает демо-курсы. Если забыли пароль админа, поменяйте `ADMIN_PASSWORD` в настройках Render: после перезапуска будет действовать новый пароль.
Каждый `git push` в `main` автоматически обновляет сайт.
На бесплатном тарифе сайт засыпает после 15 минут без посетителей, и первое открытие после этого занимает около минуты.

## Типы вопросов в тестах

- **Выбор варианта.** От 2 до 4 вариантов, один из них правильный.
- **Ввод ответа.** Ребёнок пишет ответ сам. Учитель указывает один или несколько правильных вариантов через `;`. Проверка идёт в `backend/app/grading.py`: регистр, лишние пробелы, ё/е, точка в конце и вид апострофа не важны. Если стоит флаг «сравнивать числа по значению», то `0,5` = `0.5` = `1/2`. Флаг стоит снимать, когда важна форма записи, например в задании «сократи дробь».

После сдачи теста ученик видит правильные ответы. До сдачи сервер их не отправляет.

## Редактор курса

- Уроки и вопросы можно перетаскивать за ручку ⠿: мышью, пальцем или с клавиатуры (Tab до ручки, затем стрелки ↑/↓). Изменения сохраняются автоматически: одним запросом через 400 мс после последнего перемещения.
- Вопросы можно редактировать (✏️), в том числе менять их тип. Звёзды, которые ученики уже получили, не пересчитываются.

## Структура

```
backend/app/
  main.py          # приложение, CSRF-middleware, ошибки валидации, раздача frontend/
  models.py        # таблицы: users, courses, lessons, questions, enrollments, lesson_progress, feedback, auth_sessions
  schemas.py       # валидация входных данных (Pydantic): возраст 5–14, пароль ≥ 8 и т.д.
  security.py      # scrypt-хеши паролей, серверные сессии
  deps.py          # текущий пользователь, проверка ролей
  routers/         # auth, courses (каталог + ученик), teacher, admin
  grading.py       # проверка ответов, введённых текстом
  migrations.py    # миграции схемы SQLite (PRAGMA user_version)
  seed.py          # демо-данные
frontend/
  *.html           # каркасы страниц
  js/common.js     # fetch-обёртка, шапка, экранирование, мини-разметка уроков
  js/sortable.js   # перетаскивание списков (Pointer Events + клавиатура)
  js/pages/*.js    # логика каждой страницы
  css/style.css
```

## Безопасность

- Пароли хранятся как хеши scrypt с солью. Сессии серверные: в cookie лежит случайный токен (httpOnly, SameSite=Lax), в БД хранится только его SHA-256. При блокировке пользователя все его сессии сразу становятся недействительными.
- CSRF: любой изменяющий запрос к `/api` должен нести заголовок `X-Requested-With: fetch`.
- Правильные ответы на тесты не отправляются ученику, ответы проверяет сервер.
- Всё, что вводят пользователи, экранируется на фронтенде (`esc()`). Разметка уроков применяется уже после экранирования.
- Защита от перебора паролей: не больше 10 неудачных попыток входа за 15 минут с одного IP (хранится в памяти процесса).

## Перед продакшеном

- Работать только за HTTPS и выставить `COOKIE_SECURE=1`.
- Задать `DATABASE_URL` для PostgreSQL. Для изменений схемы подключить Alembic вместо `migrations.py`.
- Удалить демо-аккаунты и создать своего админа.
- Проверить с юристом обработку персональных данных детей (в РФ это 152-ФЗ) и подготовить политику конфиденциальности.
- Лимит попыток входа вынести в Redis, если процессов будет больше одного.
